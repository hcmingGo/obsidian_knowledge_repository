# MOC - 知识管理

本 MOC 是「知识管理」领域的导航入口，聚焦 Obsidian + Claude Code 组合搭建个人知识库的方法论：分工理念、目录与标签设计、AI 协作规则、自动化机制、日常与长期维护。

## 核心概念

- [[Obsidian与ClaudeCode分工模型]] —— Obsidian 负责"存储与呈现"，Claude Code 负责"整理与执行"；用户把关信息输入和产出质量，AI 负责归档执行，且 AI 的关联判断不能盲信。
- [[文件夹管领域标签管属性原则]] —— 一级文件夹划分大领域，标签描述横向属性，文件夹嵌套不超过两层，细粒度分类交给标签和 MOC。
- [[原子化笔记与MOC主题地图]] —— `03_Knowledge/` 中信息以"一篇笔记只讲一个概念"的原子化形式归档，主题笔记数达到阈值（参考 5 篇）时生成/更新 MOC 作为导航入口。
- [[项目记忆文件设计]] —— `CLAUDE.md` 是 Claude Code 每次启动自动加载的规则文件，定义角色定位、核心原则、目录说明、标签体系、职责清单、权限边界；应作为"活文档"持续维护。
- [[ClaudeCode自定义命令机制]] —— 重复性工作通过 `.claude/commands/` 下的自定义 Slash Command（交互式）或 `-p` headless 模式（定时任务）固化为可复用命令，而非依赖不存在的 `claude run`/`ask`/`generate` 子命令。
- [[个人知识库日常工作流循环]] —— 收集 → AI 编译（`/process-inbox`）→ 知识结构化（`/update-moc`）→ 检索提问 → 知识输出（`/draft-article`）→ 周期体检（`/weekly-review`）的六环节循环。
- [[个人知识库长期维护建议]] —— 人机分工要守住、标签体系要克制（一级标签 ≤10 个）、插件宜精不宜多、备份是本地方案的责任、定期做季度体系级复盘。

## 应用场景

- 从零搭建个人 Obsidian 知识库，需要确定目录结构和标签体系时。
- 编写或修订 `CLAUDE.md`，明确 AI 在知识库中的角色边界和职责清单时。
- 想把"整理 Inbox""生成周报""写文章初稿"等重复性工作固化为可复用命令时。
- 知识库运行一段时间后，评估标签是否冗余、目录是否需要调整的定期复盘场景。
