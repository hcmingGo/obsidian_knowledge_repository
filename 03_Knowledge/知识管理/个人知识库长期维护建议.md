# 个人知识库长期维护建议

长期维护知识库的几条建议：

- **人机分工要守住**：AI 负责格式化、建链接、统计分析、初稿合成；用户负责输入高质量信息、把控分类边界、审核每次产出的准确性。AI 也会犯错、会做出看似合理实则牵强的关联，不要盲信。
- **标签体系要克制**：一级标签控制在 10 个以内（如 `#工作`、`#学习`、`#生活`），二级标签细化（如 `#学习/AI`），定期借助 AI 的周报清理冗余、僵尸标签。
- **插件宜精不宜多**：核心配置加 Dataview/Templater/Tasks 之类少数插件即可，插件太多容易拖慢启动速度、引发冲突。
- **备份是本地方案的责任**：Markdown 本地文件没有厂商锁定风险，但需要自己用 Git 仓库或云盘同步工具（Dropbox / OneDrive / 坚果云等）定期备份整个 Vault。
- **定期做体系级复盘**：每季度从更高维度审视一次知识结构——哪些领域在扩张、哪些在停滞、目录是否需要调整、`CLAUDE.md` 是否需要更新。

同时要避免几个常见坑：文件夹层级别超过两层；给 Claude Code 的权限要限定在知识库目录内，尤其 headless/定时任务场景不要图省事给全盘读写权限；`CLAUDE.md` 要当成活文档持续维护；不要迷信网上流传的"魔法命令"，遇到看起来像 CLI 子命令但官方文档查不到的写法，先用 `claude --help` 或官方文档核实真实语法。
