# 项目记忆文件设计

`CLAUDE.md` 放在知识库根目录，是 Claude Code 每次启动时自动加载的上下文文件。写清楚这份文件，等于把管理规则固化下来，避免每次都要重新解释一遍。

建议至少包含以下部分：

1. **角色定位**：说明这是专属知识库管理员，目标是什么。
2. **核心原则**：文件夹管领域、标签管属性、命名规范（如短横线命名、日期用 `YYYY-MM-DD`）。
3. **目录结构说明**：一张表，列出每个文件夹的用途和入库规则。
4. **标签体系**：状态标签（`#status/待处理`）、优先级标签（`#priority/高`）、类型标签（`#type/教程`）等，并规定层级写法 `#一级标签/二级标签`。
5. **核心职责清单**：每日消化 Inbox、维护 MOC、强制执行格式规范、每周知识网络体检、支持知识输出。
6. **权限边界**：明确哪些目录 AI 可读写（如 `00_Inbox`、`03_Knowledge`），哪些只读（如 `04_Projects`）——防止 AI 误改用户手动维护的内容。
7. **内容原则**：忠于原文、注明外部信息来源。

**关键心态**：这份文件不是一次写完就不动了。当发现 AI 反复在某件事上出错，第一反应应该是回去修改 `CLAUDE.md`，而不是每次临时纠正它——即"活文档"心态。
